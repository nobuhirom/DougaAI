# 台本を書く

**入力**: `projects/<id>/plan.md` `projects/<id>/research.md`
**出力**: `projects/<id>/script.json`

## 形式

スキーマは `src/schema/script.ts`。実例は `projects/sample/script.json`。
書いたら必ず `npm run douga -- check <id>` を通す。

## 守ること（機械が見る）

これらは `douga check` が落とすので、書きながら意識する。

| 項目 | 制約 |
| --- | --- |
| `id` | `s{セクション番号}_{種別}_{3桁連番}`。セクション番号と種別は実際の位置と一致させる |
| 字幕 | **1セリフが2行 × 28.13em に収まること**。全角なら1行28文字が上限の目安 |
| `character` | `meta.characters` に宣言したキャラのみ |
| `emotion` | normal / explain / happy / surprised / thinking / trouble |
| `visual` | 6型のみ。省略すると直前を継続、消すときは `{"type":"none"}` |
| アセット | `image.src` と `bgm` は実在するファイルのみ |

## 守ること（人が見る）

### 掛け合いにする

**一方的な説明にしない。** 説明役が3セリフ以上続いたら、聞き役に渡す。

聞き役は「なるほど」で終わらせない。`characters/<id>/persona.md` に各キャラの
ふるまいが書いてあるので、それに沿わせる。

### 結論を先に出す

企画メモの構成に従う。前置きを長くしない。

### 1セリフを短く

字幕2行に収まる長さで切る。**長い説明は複数のセリフに割る。**
セリフが変わるとビジュアルはそのまま残るので、割っても画面は崩れない。

### 調査にないことを書かない

`research.md` にない数値・バージョン・料金を書かない。
必要なら調査工程に戻る。**台本の段階で推測を混ぜない。**

### 読みを気にする

TTS は読み指定の手段を持たない（docs/05_TTS導入.md）。
読み間違えそうな固有名詞・技術用語は `reading` で TTS 用の読みだけ上書きする。
字幕には `text` がそのまま出るので原綴りを保てる。

```json
{ "text": "Remotion を使います。", "reading": "リモーション を使います。" }
```

### ビジュアルは型から選ぶ

ゼロからデザインしない。6型のどれに収まるかを考える。

| 型 | 使いどころ |
| --- | --- |
| `title` | セクションの切り替え、結論の提示 |
| `bullets` | 並列する要点。**6個まで**。1項目は1行に収まる長さ |
| `code` | コード・設定ファイル。**行数と行の長さを詰める**。長いと字が小さくなる |
| `compare` | 2つの選択肢の比較 |
| `image` | 図表・スクリーンショット。`projects/<id>/assets/` に置く |
| `none` | 掛け合いだけを見せたいとき |

型に収まらない図解が必要なら、**型を増やす提案をする**。無理に別の型へ押し込まない。

## 書いたあと

```bash
npm run douga -- check <id>          # 台本の検証
npm run douga -- build <id> --tts macos-say   # 下書き音声で尺を確認
npm run douga -- info <id>           # 尺・セリフ数・ビジュアルの内訳
```

尺が想定から大きく外れたら、企画メモの構成に戻って調整する。
