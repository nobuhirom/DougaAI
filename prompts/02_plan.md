# 企画メモを書く

**入力**: `projects/<id>/idea.json`
**出力**: `projects/<id>/plan.md`

ネタ1つを、動画1本ぶんの構成案まで育てる。台本はまだ書かない。

## 出力の形

`##` の見出しを5つ、この順で置く。すべて中身が必要（空だと `douga check` が落ちる）。

```markdown
# <仮タイトル>

## 誰に
## 何を持ち帰るか
## 構成
## 扱わないこと
## 調べること
```

## 各節に書くこと

### 誰に

想定視聴者を1〜2文で。**「初心者から上級者まで」のような誰も指さない書き方をしない。**
前提知識をどこに置くかを決める節なので、「Remotion を触ったことはないが React は書ける人」
のように具体に寄せる。

### 何を持ち帰るか

見終わった人が**何をできるようになるか / 何を判断できるようになるか**を1〜3個。
「〜が分かる」で終わらせず、その後の行動まで書く。

### 構成

セクションの並びと、各セクションで何を話すか。**結論を先に出す**。

```markdown
1. 導入 — 何の話か、なぜ今か（30秒）
2. 本編1 — …
3. 本編2 — …
4. まとめ — 持ち帰りの再掲
```

各セクションの目安尺も書く。合計が想定尺（既定5〜10分）に収まるか確認する。

### 扱わないこと

**この節が一番効く。** スコープを切らないと話が発散し、尺が伸び、結局何も伝わらない。
関連するが今回は触れないことを列挙し、なぜ外すかを添える。

### 調べること

次の工程（調査）で裏を取るべき問いを列挙する。
**推測で書ける部分と、調べないと書けない部分を分ける**のがこの節の目的。

- 数値・バージョン・料金・ライセンスは必ずここに入れる
- 「たぶんこうだったはず」と思ったものは全部ここに入れる

## 守ること

- **ネタの意図を勝手に広げない。** `idea.json` の `text` に書かれていないテーマを足さない
- 分からないことを分かったように書かない。分からないなら「調べること」へ回す
- 誇張しない。「革命的」「劇的に」のような語を使わない
- `idea.json` の `kind` が `study`（自分用の学習動画）なら、公開向けの体裁は要らない。
  自分が知りたいことに素直に構成する
