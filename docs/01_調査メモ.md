## A. JSON 中心の制作システム（実運用事例）

### 全体像

制作フローは12ステップ。

```
ネタ決め → 企画メモ → 調査 → 台本 → レビュー → ビジュアル → 音声
        → サムネイル → 組み立て → ショート → 多言語化 → 投稿
```

各工程に専任の AI エージェントが割り当てられ、成果物のチェックも確認エージェントが行い、人間が要所でレビューを挟む。

### 中核: 1枚の JSON

動画の全要素が1つの JSON に載る。台本・ビジュアル・音声・サムネイル・ショート・多言語版がすべてここから派生する。

```json
{
  "sections": [
    {
      "type": "introduction",
      "name": "セクション名",
      "lines": [
        {
          "id": "s0_intro_001",
          "character": "renka",
          "text": "セリフ本文（字幕にそのまま出る）",
          "emotion": "explain",
          "slide": "some-slide.png",
          "bgm": "calm-01"
        }
      ]
    }
  ]
}
```

ビジュアルは同じ line に `visual` フィールドを追記する形。

```json
{
  "id": "s3_main_004",
  "character": "renka",
  "text": "…",
  "emotion": "explain",
  "visual": { "type": "codeBlock", "language": "json" }
}
```

翻訳版の JSON には `durationInFrames` フィールドも現れる（音声長から算出されたフレーム数）。

**この設計が効いている点**: 多言語展開（10か国語）とショート動画生成が「機械的作業」になる。翻訳対象がセリフだけでなくビジュアル内テキスト・サムネ文言・タイトル・説明文まで及ぶが、すべて JSON にあるので一律に処理できる。

### レンダリング

Remotion を使用。**アニメーションは CSS ではなくフレーム番号から計算する**。

> CSS animation は時間が経つと勝手に動くのでレンダリングでは使えない

音声ファイルの長さを基準に各セリフの duration を厳密に計算し、キャラクターの表情・口の動き・背景アニメーション（20種類）もこのタイミングに同期させる。すべてフレーム番号からの計算なので時間経過によるズレが起きない。

Remotion 標準の編集 UI は使わず、独自の Web UI でプレビュー・調整している。

### ビジュアルは「型から選ばせる」

**これが品質担保の要**。AI にゼロから自由にデザインさせず、用意された型から選ばせる。

用意されている型:

```
比較スライド / コード表示 / コード差分 / ターミナル出力
統計カード / キーワード / スター推移 / リポジトリカード / X ポスト
```

型に収まらない図解は「**許可した部品 × レイアウトパターン（フロー / 2カラム / リスト / グリッド）**」の組み合わせで作る。

10分の動画あたり 30〜40個のビジュアルを作成。

### 機械的チェックを AI レビューの前に置く

| 仕組み | 内容 |
| --- | --- |
| zod スキーマ検証 | JSON の設定ミスをその場で検知 |
| 字幕はみ出しチェック | `MAX_LINE_WIDTH = 30.93`（em）/ `MAX_LINES = 2`。全角1em・半角0.55em で幅を見積もる |
| チャプター自動生成 | 各セクションの累積フレーム数から概要欄のタイムスタンプを生成 |

```ts
const LineSchema = z.object({
  id: z.string(),
  character: z.enum(["sharina", "renka"]),
  text: z.string().min(1),
  emotion: z.enum(["normal", "happy", "explain", /* …ほか */]),
  audioDuration: z.number().positive(),
});
LineSchema.parse(line); // 設定ミスがあればその場でエラー
```

### 人間が残る場所は絞られている

全自動にしていない工程が明確。

| 工程 | 人間の役割 |
| --- | --- |
| ネタ決め | 音声入力で気になることを列挙（起点は必ず人間） |
| 台本 | 構成案とセリフを納得いくまで書き直す |
| ビジュアルの型 | 型を作り込む段階で目視確認（字幕の重なり・見切れ） |
| サムネイル | 背景をAI複数生成から1枚選ぶ / 文言を最終決定 / 配置調整 |

サムネイルを一発生成しない理由は明確に述べられている。自動生成だと「ごちゃごちゃ / 色が多すぎ / 視線が迷う / 文字が多すぎ / 何を伝えたいのか分からない」というAIらしさ全開のサムネになりがちだから。サムネの文章は2文まで。

### 改善ループ

人間の修正と AI レビューの指摘をすべてログに残し、プロンプトとレビュー観点に還元する。

`modifications.jsonl`（人間の修正ログ）のカテゴリ:

| カテゴリ | 例 |
| --- | --- |
| `title` | 抽象的な案をツール名と数字に |
| `description` | 誇張気味の言い回しを事実ベースに |
| `tags` | 検索ワードを追加 |
| `script-fix` | 一方的な説明を二人の掛け合いに |
| `outline-fix` | 結論を先に出す構成へ組み替え |
| `component-fix` | 視線の流れに沿って図を配置換え |
| `shorts-fix` | 冒頭2秒で内容が伝わる一言に |
| `step-instruction` | 比較対象の実測値も取ってから |

`ai-review-logs.jsonl`（AIレビューの指摘ログ）は5観点: どの工程 / 何を指摘 / 深刻度（blocking・minor）/ どう直されたか / 何回目で通ったか。

```json
{
  "stepId": "multilingual-translate-es",
  "reviewer": "review-translation",
  "iteration": 1,
  "issues": [
    { "severity": "blocking", "category": "mid-sentence-cut",
      "problem": "s2_main_003 が文の途中で切れている…" }
  ],
  "fixes": []
}
```

同じ修正を人間が二度やらないよう仕組み自体を直していく、という方針。人間が直す量は回を重ねるごとに減っている。

### コスト設計

- **動画生成 AI を使わない** → 1本ごとの従量課金が発生しない。コーディングエージェントのサブスク範囲で完結し「何本作っても定額」
- **工程ごとにモデルのグレードを使い分ける** — 創造性が必要な工程（台本・ビジュアル・サムネ文言）は高性能モデル、翻訳のような決まった作業は軽量モデル
- **JSON 全体を投げず、必要な箇所だけ抜き出して渡す** — 翻訳時は `id` と `text` のペアだけを抽出し、訳文を `id` で書き戻す
- **プロンプトの骨格は共通、言語ごとの差分だけ差し込む**

### キャラクター設定はプロンプトとして文書化

`sharina.md` / `renka.md` に「基本（役割・性格・関係）」「話し方」「会話のふるまい」を記述し、AI レビューはこれと照合してキャラブレを検出する。

## B. Remotion と HyperFrames の比較

### 位置づけ

| | Remotion | HyperFrames |
| --- | --- | --- |
| 記述 | React で動画を書く | HTML と CSS で動画を書く |
| 組み立て | コンポーネントで組み立てる | Web ページを書く感覚 |
| 前提 | TypeScript の型が効く | **AI エージェント前提の設計** |
| 提供 | remotion.dev | HeyGen 社 / github.com/heygen-com/hyperframes |

HyperFrames のキャッチフレーズは "Write HTML. Render video. Built for agents."

### 最大の設計差: 時間を誰が持つか

- **Remotion**: コンポーネントが `useCurrentFrame()` で**自分から時刻を取りに行く**
- **HyperFrames**: **外のタイムラインが要素へ時刻を適用する**（`data-start` / `data-duration`）

この違いが部品の作り方に波及する。

| | Remotion | HyperFrames |
| --- | --- | --- |
| 見た目 | JSX | `<div class="clip">` |
| タイミング | `useCurrentFrame()` | `data-start` / `data-duration` |
| ロジック | state / hooks | — |
| 結果 | **部品が単体で完結** | **見た目と時間を分離管理** |

**実測されている影響**: 10分クラスの動画を HyperFrames に移すと、全シーンのタイミングが `index.html` 一か所に集積した（**343クリップ / 158シーン / 618.8秒ぶん**）。

### HyperFrames の書き方

```html
<div id="root" data-composition-id="root"
     data-width="1920" data-height="1080" data-duration="10">
  <div id="title" class="clip" data-start="3" data-duration="5" data-track-index="1">
    <h1>Hello</h1>
  </div>
</div>
```

`class="clip"` を付け忘れると出っぱなしになる（`check` が検出する）。

部品化はコンポジションで行う。呼び出し側が値を渡し、受け側が型付きで宣言する。

```html
<!-- 呼び出し側 -->
<div class="clip" data-start="10" data-duration="5"
     data-composition-src="scenes/chart.html"
     data-variable-values='{"title": "Sales 2026"}'></div>

<!-- 受け側 -->
<div data-composition-id="chart"
     data-composition-variables='[
       { "id": "title",  "type": "string", "default": "Hello" },
       { "id": "accent", "type": "color",  "default": "#7c3aed" }
     ]'>
```

音声・動画は属性で制御する。

```html
<audio id="bgm" src="assets/bgm.mp3"
       data-start="3" data-media-start="2"
       data-volume="0.8" data-playback-rate="1.5"></audio>
```

### 初期化時点で AI 向けファイルが生成される

```
$ npx hyperframes init my-video --example blank
Created my-video/
  AGENTS.md
  CLAUDE.md
  hyperframes.json
  index.html
  meta.json
  package.json
```

`AGENTS.md` と `CLAUDE.md` が最初から入る。AI エージェント前提という思想がプロジェクト構成に直接表れている。

### HyperFrames CLI の守備範囲

レンダリング以外の道具も揃っている。

| 分類 | コマンド |
| --- | --- |
| 音声処理 | `beats`（ビート検出）/ `transcribe`（単語単位の文字起こし）/ `tts` |
| 映像処理 | `remove-background` / `browser` / `capture` |
| 分析 | `lint` / `check` / `grade-compare` |
| 出力 | `render` / `publish` / `cloud` |

出力形式は MP4 / WebM / GIF / 連番画像（透過 PNG）。透過を保ったまま After Effects や Nuke に読み込める。

検出したビートに動画のカットを合わせる（拍にスナップ）こともできる。

### 検証で判明した実測値・制約

| 項目 | 内容 |
| --- | --- |
| **CSS アニメーションの代償** | 同じアニメーションで CSS Animations **92.5秒** vs GSAP **4.9秒**（**18.9倍**）。HyperFrames では GSAP 推奨 |
| ~~**音声配置の制約**~~ | ~~Audio / Video は**ルート直下にしか置けない**。子コンポーネント内に置くと再生されない → 既存の部品単位が壊れる~~ **【訂正】公式ドキュメントはこれを明確に否定している。実際の制約は「`data-start` を持つ祖先要素の内側に `<video data-start>` を置いてはいけない」という別物。→ [03_方式決定.md](03_方式決定.md#調査メモの訂正) |
| **Studio の限界** | 10分の動画を読み込ませると重くて使い物にならない（雛形程度ならサクサク） |
| **ファイル分割の作法** | 1枚の HTML にまとめると `check` から分割警告が大量に出る。分割方法は HyperFrames 独自 |
| **離散アニメーション** | 口パクのような切り替えは Remotion が簡潔（`frame % 3` の1行）。HyperFrames は `Math.floor(t/0.1) % 3` + `setAttribute` |
| **既存アニメの流用** | GSAP や Lottie を載せるのは HyperFrames のほうが楽 |
| **既存 CSS の流用** | 既にある Web ページのスタイルをそのまま動画に流用できる |

### 検査ツール

```
$ npx hyperframes check
  ✗ timed_element_missing_clip_class
      <div> has timing attributes but no class="clip"
  ✗ media_missing_id
      this audio will be SILENT in renders
```

クラスの付け忘れ、無音になる音声、色のコントラスト（公開済み動画で実測 2.28:1 を検出、WCAG AA 基準は 3:1）まで見る。

**ただし穴がある**: CSS が壊れていてもレンダリングは完走してしまう（正常終了・エラー0・警告0 で、キャラが消えた動画ができる）。Remotion では TypeScript の型でコンパイル時に止まる。

### AI への渡し方の思想が違う

- **Remotion: 知識ベース型** — API リファレンス / コード例集 / ベストプラクティスを読み込ませ、AI が知識でコードを書く
- **HyperFrames: ワークフロー型** — 作業手順が組み込まれている（サイト → 紹介動画 / PR → 解説動画 / 記事 → 要約動画）

### 検証者の結論

| | 向く条件 |
| --- | --- |
| **Remotion** | React の知識がある / 今後 Web 開発もやる / 「余白を8px詰めて」とコードの言葉で言える / 部品を育てて何本も量産し、型とテストで品質を守る |
| **HyperFrames** | React を知らず今後も Web 開発をやらない / 「いい感じに大きく」とふんわり指示したい / 画面を触ってドラッグで調整したい / プロンプトから一気に1本、HTML 1枚で完結 / **生成 AI で作った動画クリップを切り貼りして繋げる** |

学習コストの観点では「React は入口が大変だが他の開発にも活きる / HyperFrames は入口が楽だが他では使えない」。

HyperFrames の開発実績は公開4ヶ月半で GitHub Stars 38,193 / リリース 316回 / コミット 3,209回。
