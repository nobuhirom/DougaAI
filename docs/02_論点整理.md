## 1. レンダリング基盤をどうするか

### 選択肢

| 案 | 概要 |
| --- | --- |
| **Remotion** | React で書く。部品が `useCurrentFrame()` で自分の時刻を持つ |
| **HyperFrames** | HTML/CSS で書く。外のタイムラインが要素に時刻を与える |
| 両方 | HyperFrames の CLI 群（`beats` / `transcribe` / `tts` / `remove-background`）だけ道具として使い、レンダリングは Remotion |
| 自作 | Playwright 等でコマ撮りして FFmpeg で結合（HyperFrames がやっていること自体は単純） |

### 判断材料

- **量産型かワンショット型か** — 「部品を育てて何本も量産、型とテストで品質を守る」なら Remotion、「プロンプトから一気に1本」なら HyperFrames（事例Bの結論）
- 想定用途3つのうち「解説動画」「自分専用の学習動画」は**量産型**に寄る。「資料の動画化」は入力が定型なら量産型、都度バラバラならワンショット型
- 音声同期が中核になる場合、HyperFrames の「Audio はルート直下のみ」制約が効いてくる可能性がある
- 10分クラスの動画では HyperFrames Studio が重い、という実測がある

### 未決の問い

- **Q1-1**: React / TypeScript をどこまで書く前提にするか（自分で書く／AI に書かせて読むだけ、で判断が変わる）
- **Q1-2**: 1本あたりの尺はどれくらいを想定するか（10分クラスか、3分以内か）
- **Q1-3**: HyperFrames の CLI を道具として切り出して使えるか（要 公式ドキュメント確認）

## 2. データモデルをどう設計するか

事例Aの構造がそのまま参考になる。

```
script
├── sections[]
│   ├── type / name
│   └── lines[]
│       ├── id            … 安定した識別子。翻訳の書き戻し・ダイジェスト指定に使う
│       ├── character     … 話者
│       ├── text          … セリフ本文（字幕にそのまま出る）
│       ├── emotion       … 表情

## 3. ビジュアルの「型」を何にするか

事例Aの型一覧をそのまま出発点にできる。

```
比較スライド / コード表示 / コード差分 / ターミナル出力
統計カード / キーワード / スター推移 / リポジトリカード / X ポスト
