# 品質方針 — 音声・絵・画面の質をどう上げるか

作成日: 2026-09-15
前提: [03_方式決定.md](03_方式決定.md) / [06_全体計画.md](06_全体計画.md)

「Remotion で作った動画の品質が低い」「TTS が自然でない」という指摘を受けて、
何が原因で、どこを変えると効くかを整理する。

---

## 1. いまの動画が低品質に見える理由

`out/sample.mp4` の品質を決めている要素を分解する。

| 要素 | いまの状態 | 原因 |
| --- | --- | --- |
| **音声** | 機械的で平坦 | **macOS `say`（下書き用）で作った音声**。公開用の Irodori TTS はまだ接続していない |
| **立ち絵** | 記号的な SVG | `placeholder` 方式。絵の用意でパイプラインを止めないための仮のもの |
| **スライド** | 白い箱に文字 | 最小限の型しか作っていない。装飾・余白・階層の設計を入れていない |
| **動き** | 登場フェードのみ | モーションの設計をしていない |
| **レンダリング** | 1080p / H.264 / 決定的 | **問題なし**。Remotion は描いたものをそのまま焼くだけで、質を下げる要素ではない |

つまり **Remotion が悪いのではなく、Remotion に渡している素材と設計が仮のまま**。
基盤は正しく動いていて、上に載せるものがまだ無い、という状態。

これは意図した順序でもある（[04_要件定義.md](04_要件定義.md) 2章）。
「レンダリングできないものは検証できない」ので、先に配管を通した。配管が通った
いま、質を上げる工程に入る。

---

## 2. 音声

### 2.1 まず Irodori TTS を実際に聴く

いま聴いている音声は Irodori ではない。**評価はまず Irodori を立ててから**。
手順は [05_TTS導入.md](05_TTS導入.md)。

Irodori は参照音声によるゼロショットクローンと、絵文字による感情制御を持つ。
`say` とは別物のはずだが、**実聴するまで断定しない**。

### 2.2 それでも不十分だったときの選択肢

| 候補 | 実行 | 費用 | 声の固定 | 備考 |
| --- | --- | --- | --- | --- |
| **Irodori TTS** | ローカル | 無料（MIT） | 参照音声でクローン | 現行の第一候補 |
| AivisSpeech / Style-Bert-VITS2 | ローカル | 無料 | 学習で固定 | 環境構築が重い。モデルの規約は配布元次第 |
| VOICEVOX | ローカル | 無料 | キャラ固定 | 声質を選べない。キャラごとに規約あり |
| にじボイス | クラウド | 有料 | あり | 従量課金 → N6 に反する |
| ElevenLabs（日本語） | クラウド | 有料 | あり | 品質は高いが従量課金 → N6 に反する |

**N6（ランニングコストゼロ）を破る候補は、破る判断を明示的にする。**
品質のために月額や従量課金を受け入れるかは、本人が決めること。パイプライン側は
`TtsBackend` を差し替えられる構造にしてあるので、どれを選んでも配管は変わらない。

### 2.3 音声の質は TTS だけで決まらない

同じ TTS でも次で印象が変わる。

- **間**: セリフ間の 0.2 秒固定を、文末の種類（。／？／…）で変える
- **話速**: キャラごとに `voice.speed` を調整する。説明役は遅め、聞き役は速め
- **感情の使い分け**: `emotion` を `normal` ばかりにしない。絵文字制御が効く TTS なら差が出る
- **読み**: 固有名詞・数字の読み間違いは `reading` で潰す

これらは台本側の工夫で、TTS を変えなくても効く。

## 3. 絵（立ち絵・挿絵・サムネイル）

### 3.1 GPT Images で作る

画像生成を **Codex CLI の `image_gen`（gpt-image）** で行う。
ChatGPT のサブスク内で完結し、API キーも従量課金も要らない。**N6 と整合する。**

これで作るもの:

| 対象 | 用途 | 一度きりか毎回か |
| --- | --- | --- |
| **立ち絵** | キャラクター2人 × 表情6種 | 一度きり（キャラクター制作） |
| **口の差分** | 閉・半開・開 × 2人 | 一度きり |
| **背景** | 動画全体の背景 | テーマごと |
| **挿絵** | スライドの `image` 型に載せる図解・イメージ | 毎回（動画ごと） |
| **サムネイル背景** | 事例A の「複数生成して1枚選ぶ」 | 毎回 |

### 3.2 立ち絵の一貫性が最大の課題

画像生成で一番難しいのは**同じキャラを別の表情で描くと別人になる**こと。
表情6種 × 口3種を別々に生成すると、まず揃わない。

対処の方針:

1. **ベース1枚を作り込む** — 正面・無表情・口閉じ・透過背景。ここに一番時間をかける
2. **表情は「差分」で作る** — ベース画像を入力にした編集（image edit）で表情だけ変える。ゼロから描かせない
3. **口は独立パーツにする** — 口の領域だけを切り出した小画像を3枚。`character.json` の `mouth` で座標指定する仕組みは実装済み
4. **キャラクターシートを先に作る** — 髪型・服・色・目の形を文章で固定し（`persona.md` の隣に `design.md`）、毎回のプロンプトに同じ記述を入れる
5. **透過は後処理** — 生成画像は背景付きで出てくることが多い。背景除去（`rembg` か HyperFrames の `remove-background`）を通す

これでも揃わなければ、**表情の種類を減らす**（6 → 3: normal / happy / surprised）。
揃っていない6種より、揃った3種の方が動画としては上。

### 3.3 立ち絵は `sprite` にそのまま載る

`character.json` の `appearance.kind` を `sprite` に変えるだけで差し替わる。
表情・口・座標の仕組みはフェーズ1 で実装済み。**配管は変えなくてよい。**

```json
"appearance": {
  "kind": "sprite",
  "size": { "width": 1024, "height": 1536 },
  "expressions": { "normal": "expressions/normal.png", "...": "..." },
  "mouth": { "frames": { "closed": "mouth/closed.png", "half": "...", "open": "..." }, "x": 480, "y": 620, "width": 120 }
}
```

## 4. スライドと動き

### 4.1 デザインシステムを作る

いまの6型は「表示できる」だけ。質を上げるには、型に共通の設計を入れる。

| 項目 | 方針 |
| --- | --- |
| 余白と階層 | タイトル／本文／注釈のサイズ比を固定する。詰め込まない |
| 色 | 背景・パネル・強調の3色に絞る。キャラの色を強調色に使わない |
| 字 | Noto Sans JP のウェイトを 400 / 700 の2種に限る |
| 動き | 登場は1種類（フェード＋わずかな上昇）で統一。要素ごとに違う動きをさせない |
| 密度 | `bullets` は最大4項目に下げる。6は多い |

**「型から選ばせる」（P4）は、型が良くなければ意味がない。** 型の質を上げるのは
人間の仕事で、AI に任せない。

### 4.2 背景

単色グラデーションをやめ、GPT Images で作った背景（薄く・低コントラスト）を敷く。
キャラと字幕が乗る前提なので、**主張しない絵**にする。

### 4.3 場面転換

セクションの切り替わりに短いトランジションを入れる（`@remotion/transitions`）。
ただし**決定性を崩さない**範囲で。フレーム番号から計算するものだけ使う。

## 5. 全体像の見直し

12工程（[06_全体計画.md](06_全体計画.md)）に、**素材の層**を加える。

```
【一度きり】キャラクター制作
  design.md → GPT Images でベース → 表情差分 → 口差分 → 背景除去 → sprite として登録

【毎回】
  ネタ → 企画 → 調査 → 台本 → レビュー → ビジュアル → 音声 → サムネイル → 組み立て → …
                                          ↑                      ↑
                                   挿絵を GPT Images で        背景を GPT Images で
                                   （image 型に載せる）        複数生成 → 人が選ぶ
```

| 追加・変更 | 内容 |
| --- | --- |
| **キャラクター制作** | 工程外の一度きりの作業として定義する。成果は `characters/<id>/` |
| **ビジュアル（工程6）** | 型を選ぶだけでなく、`image` 型の挿絵を GPT Images で作る |
| **サムネイル（工程8）** | 背景を GPT Images で複数生成し、人が選ぶ（事例A の方式そのまま） |
| **音声（工程7）** | Irodori を接続し、実聴して評価する |

**画像生成はエージェントが行う**（Codex CLI を叩くのはエージェント）。パイプラインが
画像生成 API を呼ぶのではない。[06_全体計画.md](06_全体計画.md) 1章の原則は変えない。

## 5.1 テーマ — 見た目・声・書き方を束ねる（2026-09-16 追記）

「企業っぽい配色と装飾とアナウンサーの声」「カジュアルな解説と掛け合い」のように、
台本の書き方・ビジュアル・音声・サムネイルは**動画の種類ごとにまとめて変わる**。
これを `themes/<id>/` として束ねる。

```
themes/<id>/
├── theme.json   配色（背景・パネル・強調・コード・字幕）、形式の既定、BGM の既定と音量
└── style.md     台本・ビジュアル・声・サムネイルの方針。手順書の末尾に足して使う
```

台本は `meta.theme` でテーマを選ぶ。プロジェクトごとに違ってよい。

| 何が | どこで効くか |
| --- | --- |
| 配色 | ビルド時にマニフェストへ埋め込み、Remotion が読む。コード側に色を固定しない |
| 形式（掛け合い / 紙芝居） | テーマの既定。台本の `meta.format` で上書きできる |
| 文体 | `style.md` を手順書に足す。`douga next` が案内する |
| 声 | `style.md` に「どの声を使うか」を書き、キャラクターの `voice.id` で選ぶ |
| サムネイル | `style.md` の方針（フェーズ5 で使う） |

いまあるテーマ: `default`（解説・ダーク・掛け合い）、`corporate`（企業向け・ライト・紙芝居・アナウンサー）。

## 6. 順序

| 順 | やること | なぜ先か |
| --- | --- | --- |
| 1 | **Irodori TTS を接続して実聴** | 音声は動画の印象の半分以上を決める。評価しないと次が決まらない |
| 2 | **キャラクター制作**（GPT Images でベース1枚 → 表情3種から） | 立ち絵が仮のままだと、他を直しても仮に見える |
| 3 | スライドのデザインシステム | 素材が揃ってから合わせる |
| 4 | 背景・挿絵・サムネイル | 3 の型に載せる |

**1 と 2 は並行できる。** どちらも配管を変えないので、いつ入れても動画には反映される。
